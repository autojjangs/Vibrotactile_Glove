# Vibrotactile_Glove

실내 영상 기반 스마트 장갑 실험을 위한 독립 프로젝트입니다. 기존 Smart_Helmet은 변경하지 않습니다.
Python 3.11 이상, 라즈베리파이 Bluetooth LE, 좌우 ESP32-C3, 기존 WS281x 방향지시등을 사용합니다.

## 구현된 실험 규칙

| 항목 | Baseline | Proposed |
|---|---|---|
| 사전 안내 | 해당 방향 장갑에 기본 2회 진동 | 동일 |
| 입력 허용 | 첫 사전 진동의 시작 보고부터 | 동일 |
| 유효한 손 | 안내 방향의 손 | 동일 |
| 점등 전 접촉 | 점등하고 반복 진동으로 즉시 전환 | 해당 지점의 자동 점등을 취소 |
| 점등 후 접촉 | 소등 및 반복 진동 정지 | 무시 |
| 취소 후 재접촉 | 해당 없음 | 취소 유지 |
| 지점 통과 | 자동 소등 및 반복 진동 정지 (정상 동작) | 자동 소등 및 반복 진동 정지 |

전극을 붙이고 유지하면 1회이며, 해제 후 다시 붙여야 다음 접촉입니다. 해제와 무시된 접촉도 기록합니다.
취소한 경우 별도 성공 진동을 추가하지 않으며 남은 사전 안내는 원래대로 완료합니다.
Baseline에서 사전 안내 도중 점등하면 남은 안내를 중단하고 반복 피드백으로 바꿉니다.
첫 사전 안내 전에 이미 붙이고 있던 천은 안내가 시작되어도 새 입력으로 계산하지 않습니다.
정답 정보(expected_action)는 기록에만 쓰며 자동 점등을 막는 조건으로 사용하지 않습니다.

## 먼저 해볼 모의 실행

장갑, 라즈베리파이, 별도 Python 패키지 없이 가능합니다.

```powershell
cd D:\Vibrotactile_Glove
python -m vibro --simulate --condition baseline
```

준비 완료 후 `start`를 입력하면 T=0이 시작됩니다.
`left press`, `left release`, `right press`, `right release`로 접촉을 모의 입력합니다.
`status`는 상태 확인, `mark 내용`은 실험자 메모, `abort` 또는 Ctrl+C는 중단입니다.
한 프로세스는 한 시행을 진행합니다. 다음 시행은 새 명령으로 시작합니다.

자동 검증용 10초 예시(실제 경로 타임스탬프가 아닙니다):

```powershell
python -m vibro --simulate --autostart --condition baseline --input-script tests/demo_inputs.json
python -m vibro --simulate --autostart --condition proposed --input-script tests/demo_inputs.json
python -m unittest discover -v
```

이 입력 예시는 모든 정답 수행 예시가 아니라 조기 입력, 반대 손, 유지, 재접촉 등을 확인하는 시나리오입니다.

## 설정 파일

`config/settings.json`:
- 왼쪽 BLE MAC: 70:AF:09:34:C3:A6
- 오른쪽 BLE MAC: 70:AF:09:33:09:1E
- `haptics.preview`: 사전 안내의 on_ms, off_ms, count
- `haptics.feedback`: 점등 중 반복 진동의 on_ms, off_ms. 소등까지 무한 반복합니다.
- off_ms는 **한 진동 종료 후 다음 진동 시작까지 쉬는 시간**입니다.
- 현재 사전 안내는 600ms ON + 400ms OFF, 2회입니다. 시작 간격은 1초이며 두 번의 진동이 끝나기까지 1.6초입니다. 확정된 실험 자극값은 아닙니다.
- 현재 점등 피드백은 200ms ON + 600ms OFF를 반복합니다. 사전 안내는 길게 두 번, 점등 피드백은 짧게 반복하도록 구분했습니다. 진동 길이와 간격을 바꾼 것이며 출력 강도는 동일합니다.
- LED 설정은 참고 코드의 실제 값(20개, 왼쪽 17~19, 오른쪽 0~2, GPIO18)을 옮긴 초기값입니다. 실제 배선과 대조하세요.
- `max_dispatch_lag_s`: 시간표 실행 지연 허용치(기본 0.5초). 초과하면 시행을 무효로 중단합니다.

## ESP32-C3 준비

1. Arduino IDE의 Espressif esp32 보드 패키지 **3.3.2**를 설치하고 보드는 **ESP32C3 Dev Module**, **USB CDC On Boot: Enabled**를 선택합니다.
2. `firmware/VibrotactileGlove/VibrotactileGlove.ino`를 엽니다.
3. 같은 폴더의 `config.h`에서 `CONTACT_PIN=3`으로 설정되어 있습니다. ESP32-C3 SuperMini의 GPIO3에 전극 천 A를 연결하고, GND에 천 B를 연결합니다.
4. 왼쪽 장갑은 `GLOVE_SIDE=0`, 오른쪽은 `GLOVE_SIDE=1`로 각각 업로드합니다.
5. `MOTOR_PIN=4`는 참고 코드의 초기값이므로 실제 연결과 맞추세요.
6. 전극 천 A는 GPIO3, 전극 천 B는 GND에 연결합니다. GPIO는 INPUT_PULLUP으로 읽으며 전극에 5V를 연결하지 않습니다. 5V/GND/3V3가 있는 줄을 USB 쪽부터 세면 GPIO3은 다섯 번째, GND는 두 번째입니다. 실제 보드의 3 및 G/GND 인쇄를 확인하세요.
7. 모터 핀은 기존 모터 구동 모듈의 IN에 연결합니다. 모터 자체를 GPIO에 직접 연결하지 않습니다.
8. 시리얼 모니터(115200)에서 손 구분, GPIO, BLE 주소를 확인합니다. 주소가 다르면 settings.json을 갱신합니다.

BLE UUID와 패킷이 새로 정의되어 있으므로 **두 장갑 모두 새 펌웨어**가 필요합니다.
기본 접촉 안정화 시간(DEBOUNCE_MS)은 30ms이고 config.h에서 변경할 수 있습니다.
기록되는 접촉 시각은 이 안정화 처리가 완료된 시각입니다. 원시 GPIO 바운스 하나하나는 실험 입력으로 기록하지 않습니다.

## 라즈베리파이 설치와 실행

프로젝트 전체를 라즈베리파이에 복사하고 해당 디렉터리에서:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
bash run --scan
```

실제 경로의 영상 자동 재생에는 아래의 mpv 설치와 media 파일 복사가 추가로 필요합니다.

기존 방향지시등의 GPIO18/PWM 배선이라면 참고 시스템에서 사용하던 오디오/PWM 설정이 필요할 수 있습니다.
기존 스마트 헬멧 프로그램과 새 실험 프로그램이 같은 LED 장치를 동시에 제어하지 않도록 하세요.

### 짧은 실행 명령

프로젝트 폴더에서 아래 명령을 입력하면 네 가지 배정 조건 중 하나를 고른 뒤 참가자 코드와 시행 번호를 입력합니다.

```bash
bash run
```

| 배정 코드 | 경로 | 방식 | 바로 선택 |
|---|---|---|---|
| `1b` | 경로 1 | 수동 (baseline) | `bash run 1b` |
| `1p` | 경로 1 | 반자동 (proposed: 자동 점등·취소) | `bash run 1p` |
| `2b` | 경로 2 | 수동 (baseline) | `bash run 2b` |
| `2p` | 경로 2 | 반자동 (proposed: 자동 점등·취소) | `bash run 2p` |

메뉴에 `1b`, `1p`, `2b`, `2p` 중 하나를 입력하거나 위 바로 선택 명령을 사용하세요.
그다음 참가자 코드를 직접 입력하며, 시행 번호는 Enter를 누르면 `01`을 사용합니다.
참가자 배정표에 맞춰 선택하세요. 선택한 경로·방식·참가자·시행은 연결 전에 화면에 표시됩니다.
네 가지 조합은 기존 경로 파일과 baseline/proposed 로직을 사용하며, 로그에도 경로와 조건이 각각 기록됩니다.
`test`, `free` 연습도 같은 메뉴에서 선택할 수 있습니다.

기존처럼 경로·방식·참가자·시행을 한 줄로 모두 지정할 수도 있습니다:

```bash
bash run 1 b P01 01
bash run 1 p P01 02
bash run 2 b P02 01
bash run 2 p P02 02
```

실제 장비 실행에서는 필요한 `sudo`를 자동으로 적용하며 암호를 물을 수 있습니다.
양쪽 장갑 연결 준비가 완료된 뒤 기존과 같이 `start`를 입력해야 시간이 시작됩니다.
종료 후 같은 명령으로 다시 실행할 수 있으며, Ctrl+C로 중단합니다.

| 용도 | 명령 |
|---|---|
| 시간 제한 없는 진동·방향지시등 체험 | `bash run free` |
| 40초 자동 점등·취소 연습 | `bash run test` |
| 40초 수동 점등·소등 연습 | `bash run test b` |
| BLE 장갑 검색 | `bash run --scan` |
| 경로 1 시간표·설정 검사 | `bash run 1 --validate` |
| 장비 없이 경로 1 모의 실행 | `bash run 1 b P01 01 --simulate` |
| 도움말 | `bash run --help` |

연습은 참가자 `TEST`, 시행 `PRACTICE`로 기록합니다.
모의 실행·검색·시간표 검사는 `sudo` 없이 실행합니다.
상세 로그는 명령 끝에 `--verbose`를 추가합니다.

기존의 긴 명령도 계속 사용할 수 있습니다. 별도 설정 파일이나 로그 저장 위치 등 세부 옵션을 지정할 때 사용하세요:

```bash
sudo .venv/bin/python -m vibro --route routes/route_1.json --condition baseline --participant P01 --trial 01
```

실제 경로 파일에는 작성본의 지점별 타임스탬프를 반영했으며 `ready: true`입니다.
두 경로 모두 **내비 영상 시작 0초**를 기준으로 합니다. 실제 경로 실행은 기본적으로 두 영상을 자동으로 준비하고,
`start` 입력 후 내비 재생 위치에서 추정한 0초에 실험 시간표를 맞춥니다.

| 경로 | 안내 지점 | 회전 / 직진 | 실험 종료 |
|---|---|---|---|
| route_1 | 6개 | 4개 / 2개 | 279.417초 |
| route_2 | 6개 | 4개 / 2개 | 263.917초 |

종료 시각은 사용자가 확인한 내비 영상 끝이며, 직진 단서는 작성본 E열 값을 사용합니다.
같은 경로 JSON을 baseline/proposed에 공통으로 사용합니다. 위 실행 예시의 경로·조건 조합은 참가자 배정에 맞게 바꿉니다.
장비 연결만 예시 시간표로 점검하려면 명시적으로 `--allow-demo`를 붙입니다:
```bash
sudo .venv/bin/python -m vibro --allow-demo --condition proposed
```

## 두 HDMI 화면에서 영상 자동 재생

대상 구성은 Raspberry Pi 4 Model B, Debian 13 (trixie), Wayland입니다.
큰 모니터에는 주행 영상, 7인치 1024×600 LCD에는 내비 영상을 표시합니다.
내비 원본은 668×668이므로 비율을 유지한 600×600 영역으로 표시되며 좌우에 여백이 생깁니다.
주행 영상과 내비 안내의 소리를 모두 라즈베리파이 데스크톱의 기본 오디오 출력으로 재생합니다.

처음 한 번 라즈베리파이에서 플레이어를 설치하세요:

```bash
sudo apt update
sudo apt install mpv
```

네 영상은 프로젝트의 `media/` 폴더에 원래 이름으로 복사합니다.
영상 파일은 용량 때문에 Git에서 제외하므로 **git clone/pull만으로는 내려오지 않습니다.**

- 경로1 내비 영상.mp4
- 경로1 주행 영상.mp4
- 경로2 내비 영상.mp4
- 경로2 주행 영상.mp4

이미 다른 폴더에 옮겼다면 `config/settings.json`의 `video.media_dir`에 그 절대 경로를 지정해도 됩니다.
영상의 두 시작 지점은 편집에서 서로 맞춰져 있어야 합니다. 프로그램은 각 파일의 0초부터 재생합니다.

### 화면 배치와 시작

1. 라즈베리파이 화면 설정에서 두 디스플레이를 **확장 모드**로 설정합니다. LCD는 1024×600으로 설정합니다.
2. **라즈베리파이 데스크톱의 터미널**에서 `bash run 1b` 등 원하는 배정을 실행합니다. 앞에 sudo를 붙이지 않아도 됩니다.
3. 두 영상이 작은 창으로 첫 장면에서 대기합니다. 영상창이 터미널을 가리면 Alt+Tab으로 터미널에 돌아옵니다.
4. 장갑 연결과 영상 준비가 모두 완료된 READY 뒤 `start`를 입력합니다.
5. 두 영상이 지정 화면의 전체 화면으로 전환되고, 약 1초의 화면 배치 대기 후 재생합니다.
6. 두 영상의 재생 진행을 확인한 뒤 내비 재생 위치에서 0초의 Pi 시각을 추정하여 실험 시간표를 시작합니다.
7. 종료·중단·영상 오류 때 두 플레이어와 장갑·LED를 함께 종료합니다. Ctrl+C는 터미널에서 입력합니다.

기본 `video.screens`는 `{"driving": 0, "navigation": 1}`입니다.
화면 번호는 HDMI 커넥터 인쇄 번호와 일치한다고 보장되지 않으므로 첫 시험 때 화면을 확인하세요.
반대로 나온다면 `{"driving": 1, "navigation": 0}`으로 바꿉니다.
두 영상이 같은 화면에 배치되거나 실행 중 출력 화면이 바뀌면 실험을 중단합니다.
영상의 창을 닫으면 시행도 중단됩니다. 재생·탐색 단축키는 비활성화되어 있습니다.

LED 제어에는 기존처럼 sudo가 적용됩니다. 영상 프로세스는 로그인한 일반 사용자 권한으로 실행하며,
실행기가 Wayland/X11·오디오 연결에 필요한 화면 환경을 전달합니다. 보안 설정이나 화면 서버 접근 권한은 변경하지 않습니다.
SSH만으로 실행하면 화면 환경을 찾지 못할 수 있으므로 최초 점검은 데스크톱 터미널에서 진행하세요.

### 먼저 영상만 확인하기

```bash
bash run 1b --simulate --videos
```

참가자 코드는 TEST 등으로 입력합니다. 실제 장갑·LED는 연결하지 않고 두 영상을 실제 화면에 띄웁니다.
반면 `--simulate`만 사용하면 기존처럼 영상도 띄우지 않습니다.
장비만 기존 방식으로 확인하려면 `bash run 1b --no-video`로 실행합니다.
40초 연습과 자유 체험은 계속 영상 없이 동작합니다.

### 내비 화면이 멈추고 음성만 나올 때

현재는 두 플레이어 모두 소프트웨어 디코딩(`--hwdec=no`)을 기본으로 사용합니다.
사용자가 가속을 끈 내비 단독 재생은 정상이라고 확인했으므로 같은 디코딩 방식을 사용합니다.
다만 동시 실행에서는 가속을 꺼도 내비 화면이 잠깐 움직인 뒤 정지하고 음성은 계속 나오는 증상이 보고됐습니다.
사용자 로그에서 `vo/gpu/libplacebo`의 `VK_ERROR_OUT_OF_HOST_MEMORY` 및 `Failed (re)creating swapchain!` 반복을 확인했습니다.
현재 두 플레이어에 `--vo=gpu --gpu-api=opengl`을 지정하여 오류가 발생한 Vulkan 출력 경로를 사용하지 않도록 합니다.
Wayland 데스크톱에서는 `--gpu-context=wayland`로 네이티브 Wayland/EGL을 사용하며, X11 데스크톱에서만 x11egl을 선택합니다.
이는 영상 해독 옵션인 hwdec와 별개의 화면 출력 설정입니다. 오류 이름만으로 시스템 RAM 총량 부족을 확정하지는 않습니다.
`config/settings.json`을 편집하지 않아도 새 기본값이 적용되어 기존 화면 번호는 유지됩니다.
명시적으로 `video.hwdec`를 설정할 경우 `"no"`, `"auto"`, `"auto-copy"`를 사용할 수 있습니다.
실행 시 `소프트웨어 재생 (가속 끔) · OpenGL 화면 출력` 표시로 적용 여부를 확인하세요.
`--force-render` 강제 갱신 옵션은 Pi에서 재생 악화가 보고되어 제거했습니다. 준비 메시지에 `화면 갱신 유지`가 나오면 이전 버전입니다.
mpv의 오류 메시지를 IPC로 수신하며, `vo` 또는 `vo/` 출력 모듈에서 error/fatal이 발생하면 즉시 시행 중단을 요청합니다.
재생 시계가 계속 흐르더라도 알려진 화면 출력 오류를 무시한 채 실험을 이어가지 않습니다.
OpenGL 변경 후 실제 Pi에서 사용자가 두 영상의 정상 재생을 확인했습니다. 두 경로 전체 길이의 드리프트 및 장갑·LED와의 시간 일치는 추가 확인해야 합니다.
옵션 근거: [mpv 공식 gpu-api / gpu-context 설명](https://github.com/mpv-player/mpv/blob/v0.40.0/DOCS/man/options.rst).

각 시행 로그 폴더에 `mpv_navigation.log`와 `mpv_driving.log`를 별도로 저장합니다.
이 파일에는 플레이어 버전, 디코더·화면 출력 및 재생 오류 진단 정보가 들어갑니다.
기본 실험 로그에는 이 상세 출력을 섞지 않습니다. 다시 멈추면 두 파일과 `events.csv`를 함께 확인합니다.
음성이 계속 나오는 동안 재생 시간만 정상일 수 있으므로 `재생 시각 차이 0초`만으로 화면 갱신을 판단하지 마세요.
프로그램은 물리적 LCD 화면 갱신을 직접 측정하지 않습니다.

### 로그 폴더 권한 오류가 날 때

기존 버전에서 sudo로 실행하면 `logs`가 root 소유로 만들어질 수 있습니다.
이 상태에서 `--simulate --videos`를 일반 사용자로 실행하면 새 시행 폴더를 만들 때
`Configuration/setup error: [Errno 13] Permission denied: .../logs/...`가 발생합니다.

라즈베리파이의 **프로젝트 폴더에서** 아래 명령을 한 번 실행한 뒤 다시 시도하세요:

```bash
sudo chown "$(id -u):$(id -g)" ./logs
bash run 1b --simulate --videos
```

logs 폴더 자체의 소유자만 현재 사용자로 바꿉니다. 기존 시행 폴더나 로그 내용은 변경하지 않습니다.
새 버전은 sudo 실행으로 **새로 만드는** 로그 폴더와 시행 파일을 sudo를 호출한 사용자 소유로 저장합니다.
이미 존재하는 폴더의 소유권이나 권한은 자동 변경하지 않습니다.

### 동기화 기록과 허용 범위

`video_started`에는 재생 시작 요청 시각, 추정된 내비 0초 시각, 두 영상의 시각 차이가 기록됩니다.
`video_sync_sample`에는 약 1초마다 양쪽 재생 위치와 실험 경과시간, 응답 지연을 기록합니다.
이 주기적인 값은 CSV에 저장하고 기본 화면에서는 숨깁니다.
사용한 영상 파일 경로·SHA-256·해상도·길이는 `video_file_ready`에 기록합니다.

기본 설정은 0.1초 간격 검사, 영상 간 차이 0.2초, 실험 시계와 영상 차이 0.2초,
위치 조회 왕복 지연 0.1초입니다. 시간 차이 또는 조회 지연이 이 기준을 넘으면 경고를 남기고 계속 진행합니다.
초과 상태가 **연속 2초 이상** 관측될 때만 동기화 오류로 중단합니다. 그 전에 모든 시간 기준을 회복하면
회복 로그를 남기고 누적 시간을 초기화합니다. 문제의 종류나 영상이 바뀌어도 정상 회복 없이 계속 초과하면 같은 기간으로 계산합니다.
조회가 느렸던 측정값은 정확한 시간 차이로 판단하지 않고 조회 지연으로 기록합니다.
실제 재생 정지·탐색·배속 변경·조기 종료·플레이어 오류와 통신 응답 시간 초과는 즉시 중단합니다.
`video_sync_warning`, `video_sync_recovered`, `video_sync_persistent`에 최초 초과·회복·지속 중단과 최대 관측값을 기록합니다.
초과 중에 시행이 끝나면 `video_sync_unresolved`로 회복 미확인 상태를 남깁니다.
시작 시 내비 위치 조회가 느리면 기존 시작 제한 시간 안에서 다시 조회한 뒤 기준 시각을 정합니다.
대기 시간은 `video.sync_fault_after_s`로 바꿀 수 있으며, 기존 설정 파일에 없으면 **2.0초**가 적용됩니다.
새 정책의 실제 적용값은 `video_ready`의 `sync_policy`에 기록합니다.
자동 탐색이나 배속 보정으로 자극을 건너뛰지는 않습니다.
허용치는 `config/settings.json`의 `video`에서 조정할 수 있으며, 0.2초는 장비 점검용 초기 허용치입니다.
본 실험의 허용 오차는 실제 장비의 지연을 측정해 정해야 합니다.

이 기록은 **플레이어가 보고한 재생 시각에 근거한 소프트웨어 추정값**입니다.
모니터·LCD의 실제 발광 시각이나 소리 출력 지연을 측정한 값이 아니며, 프레임 단위의 완전 일치를 보장하지 않습니다.
Pi에서 두 화면 배치, 두 오디오, 영상 진행 및 실제 표시 시각 차이를 확인한 후 본 실험에 사용하세요.

## 본 실험 전 전극 조작 연습

양쪽 전극으로 직접 켜기·끄기·취소를 익히는 프로그램입니다.
영상 없이 장갑과 방향지시등만 사용하며, 기존 펌웨어로 실행합니다.

```bash
bash run practice
```

연결 후 **큰 글씨와 버튼이 있는 별도 연습창**이 열립니다. 전극 천을 떼어 놓고
`왼쪽 연습 시작` 또는 `오른쪽 연습 시작` 버튼을 누르세요. 기본은 수동 조건이며 `start`는 필요 없습니다.
창에서 수동/반자동 조건, 양쪽 전극 접촉 상태, 점등/취소 결과, 남은 시간을 확인할 수 있습니다.
상태에 맞게 지금 해야 할 동작을 안내합니다. 전극을 떼어도 직전 점등·취소 결과가 계속 표시됩니다.
F11은 전체 화면, Esc는 전체 화면 해제입니다. 큰 모니터로 창을 옮겨 사용하세요.

라즈베리파이 데스크톱에서 실행하며, 창 표시 모듈이 없다면 한 번 설치합니다.

```bash
sudo apt install python3-tk
```

Pi의 GPIO 제어는 기존 권한으로 실행하고 연습창은 데스크톱 사용자 권한으로 엽니다.
추가 영상은 사용하지 않습니다. 창의 `연습 종료` 또는 닫기 버튼도 양쪽 장갑과 LED를 정지합니다.
기존 터미널 방식은 `bash run practice --terminal`로 실행합니다. 아래 단축키도 사용할 수 있습니다.

| 입력 | 동작 |
|---|---|
| `1` / `2` | 왼쪽 / 오른쪽 연습 회차 시작 |
| `b` / `p` | 수동 / 반자동 조건으로 전환 (진행 중인 회차는 중단) |
| `r` | 직전 손으로 다시 연습 |
| `0` | 현재 회차 중단, 양쪽 점등·진동 정지 |
| `status` | 현재 방향지시등·입력 가능 상태 확인 |
| `q` | 종료 |

한 회차는 기본 12초이며, 끝나면 다음 선택을 기다립니다. 원하는 횟수만큼 반복할 수 있습니다.

- **수동:** `1` → 사전 진동을 느낀 뒤 왼쪽 전극 접촉 → 점등·반복 진동 →
  전극을 떼었다 다시 접촉 → 소등. `2`로 오른쪽도 연습합니다.
- **반자동 취소:** `p` → `1` → 사전 진동 뒤, 회차 시작 후 4초가 되기 전에 왼쪽 전극 접촉 →
  자동 점등 취소. 남은 사전 안내 진동은 계속되며 취소를 알리는 별도 진동은 추가하지 않습니다.
- **반자동 점등 관찰:** `r` 또는 `2` → 전극을 접촉하지 않고 기다리기 →
  회차 시작 후 4초에 자동 점등·반복 진동, 12초에 통과·소등.

두 조건 모두 회차 시작 후 12초에 통과한 것으로 처리해 자동 소등합니다.
수동에서 사전 안내 도중 점등하면 남은 안내 진동을 중단하고 점등 피드백으로 전환합니다.
반자동은 점등 후 접촉으로 끌 수 없고, 이미 취소한 회차에서 다시 접촉해도 취소가 유지됩니다.
계속 붙인 천은 1회 입력이며, 회차·조건을 바꿔도 반드시 떼었다 다시 접촉해야 새 입력입니다.
다른 손의 접촉, 안내 전 접촉, 전극 해제도 화면에 표시하고 로그에 기록합니다.

처음부터 반자동으로 실행하려면 `bash run practice p`를 사용합니다.
진동은 `config/settings.json`의 `haptics` 설정을 공유합니다. 연습 시각만 바꾸려면 같은 파일의
최상위에 `"practice": {"auto_on_s": 4.0, "pass_s": 12.0}`을 추가합니다.
`auto_on_s`는 양수이며 `pass_s`보다 작아야 합니다. 두 시각은 사전 안내 요청 시점을 기준으로 합니다.
실제 경로 시간표와 영상 동기화 검사에는 영향을 주지 않습니다.

로그 폴더는 `TEST_CONTACT_PRACTICE_practice`로 식별됩니다. 세션 정보는 `scored: false`이며,
입력·점등 등 규칙 이벤트의 condition에는 그때 선택한 `baseline` 또는 `proposed`가 기록됩니다.
본 실험 결과에 포함하지 않습니다. 종료·Ctrl+C·연결 오류 시 출력을 정지합니다.
장비 없는 모의 검사는 `bash run practice --simulate`로 실행하고,
`left press`, `left release`, `right press`, `right release`로 접촉·해제를 입력합니다.

## 시간 제한 없는 자유 체험

사전 안내 진동과 방향지시등·점등 진동을 원하는 만큼 경험하려면:

```bash
bash run free
```

양쪽 장갑 연결 후 READY가 표시되면 아래 숫자를 입력하고 Enter를 누릅니다.
`start`를 입력할 필요가 없으며 종료할 때까지 시간 제한 없이 사용할 수 있습니다.

| 입력 | 동작 |
|---|---|
| `1` | 왼쪽 사전 안내 진동 |
| `2` | 오른쪽 사전 안내 진동 |
| `3` | 왼쪽 방향지시등 + 반복 점등 진동 |
| `4` | 오른쪽 방향지시등 + 반복 점등 진동 |
| `0` | 양쪽 방향지시등과 진동 모두 끄기 |
| `q` | 종료 |
| `help` | 사용법 다시 보기 |

예: `1` → 사전 안내 체험 → `3` → 점등 진동을 충분히 체험 → `0`.
같은 숫자를 다시 입력하면 해당 동작을 처음부터 재생합니다.
새 동작을 고르면 기존 점등과 진동을 먼저 정지합니다.

사전 안내는 현재 설정의 2회 패턴을 재생한 뒤 스스로 멈춥니다.
방향지시등과 점등 피드백 진동은 `0`, 다른 동작, 종료를 입력할 때까지 유지됩니다.
진동 패턴은 `config/settings.json`을 그대로 사용하며 펌웨어 재업로드가 필요 없습니다.
종료, Ctrl+C, 연결 오류 때는 출력을 정지하고 연결을 닫습니다.

이 모드는 자극 구분을 위한 자유 체험입니다. **전극 접촉·해제는 기록만 하며 점등이나 취소를 조작하지 않습니다.**
수동·반자동의 전극 동작은 `bash run practice` 또는 아래 40초 연습을 사용하세요.
자유 체험은 참가자 `TEST`, 시행 `FREE`, 조건 `free`로 별도 기록되며, 경과시간은 프로그램 실행 기준입니다.
장비 없는 확인은 `bash run free --simulate`, 상세 통신 기록 표시는 `--verbose`를 덧붙입니다.

## 40초 진동 비교 연습

`routes/haptic_practice_40s.json`은 10초 간격으로 4번 반복하는 장비 연습용 시간표입니다.
왼쪽·오른쪽·왼쪽·오른쪽 순서로 안내합니다. 영상 없이 사용할 수 있으며,
`start` 이후 40초에 종료됩니다. 매 회차마다 접촉하거나 가만히 있는 선택을 직접 합니다.

| 회차 | 장갑 | 사전 안내 시작 | 자동 점등 시각 | 소등·입력 마감 |
|---|---|---|---|---|
| 1 | 왼쪽 | 1초 | 3초 | 9초 |
| 2 | 오른쪽 | 11초 | 13초 | 19초 |
| 3 | 왼쪽 | 21초 | 23초 | 29초 |
| 4 | 오른쪽 | 31초 | 33초 | 39초 |

라즈베리파이에서 접촉으로 자동 점등을 취소하거나, 입력 없이 자동 점등을 관찰하려면:

```bash
bash run test
```

`READY`가 나오면 양쪽 전극 천을 떼어 놓고 `start`를 입력합니다.
첫 사전 안내 진동을 느낀 뒤 자동 점등 시각 전까지 **안내받은 손**의 천을 한 번 붙였다 떼면 그 회차의 자동 점등이 취소됩니다.
접촉하지 않으면 해당 방향지시등이 켜지고 점등 피드백 진동이 6초 동안 반복됩니다.
취소한 회차에도 남은 사전 안내 진동은 그대로 완료됩니다. 다음 회차 전에 전극 천을 떼어 주세요.
자동 점등 이후의 접촉은 취소로 처리하지 않으며, 표의 소등 시각에 자동으로 종료합니다.

현재 설정에서 사전 안내는 **0.6초 진동, 0.4초 쉼, 0.6초 진동**이며,
점등 피드백은 **0.2초 진동, 0.6초 쉼**을 소등까지 반복합니다.
강도 조절은 추가하지 않았습니다. 이 연습은 기존 펌웨어로 실행할 수 있습니다.
패턴은 현재 `config/settings.json`의 값을 사용하므로 설정을 바꾸었다면 그 값이 적용됩니다.

수동 점등·소등을 비교하려면 `bash run test b`로 실행합니다.
Baseline에서는 사전 안내 이후 첫 접촉으로 켜고, 해제 후 다시 접촉하면 끕니다. 켜둔 상태로 지점을 통과하면 자동 소등하고 반복 진동도 정지합니다. 통과 시까지 직접 끄지 않아도 소등 누락으로 기록하지 않습니다. 점등 입력 없이 가만히 있으면 점등하지 않습니다.
반복하려면 종료 후 같은 명령을 다시 실행합니다. 중간 중단은 Ctrl+C입니다.

이 시간표는 진동 비교 연습이므로 정답·오답 평가용으로 사용하지 않습니다.
필수 필드인 `expected_action`은 모두 `turn`으로 채웠으며, 접촉 취소를 제한하지 않습니다.
프로그램의 영상 동기화 안내 문구는 실제 실험용 공통 메시지이므로 이 연습에서는 영상을 재생할 필요가 없습니다.

## 경로 타임스탬프 입력

`routes/route_1.json`, `route_2.json`에는 2026-11-16 작성본의 시간을 반영했습니다.
시간표를 수정할 때는 기존 지점 ID를 유지하고, 확정 전에는 ready를 false로 두세요. 필드는 다음과 같습니다.

- route_id: 경로 식별자
- ready: 실험에 사용할 타임스탬프가 확정되었는지
- demo: 실제 경로는 false
- duration_s: 영상 기준 시행 종료 시각
- events: 안내 지점들의 배열
- 각 지점: id, direction(left/right), expected_action(turn/straight), preview_s, auto_on_s, pass_s, cue_s(직진 단서)
- 시간은 모두 내비 영상 시작 기준 초 단위 숫자입니다.
- videos는 자동 재생할 두 파일의 이름입니다. time_reference, source와 각 지점의 location, notes는 원본 확인용 정보입니다. notes로 별도 TTS를 생성하지 않으며, 영상에 녹음된 소리를 재생합니다.
- 이전 지점 통과 < 다음 사전 안내 < 자동 점등 < 지점 통과 순서여야 합니다.
- 직진 단서는 첫 사전 안내 이전 또는 같은 시각이어야 합니다. ‘처음부터 켜지 않음’이라는 정답 기준을 위한 제약입니다.
- Baseline에서도 auto_on_s를 기록하지만 그 시각에 자동 점등하지 않습니다.

`python -m vibro --route routes/route_1.json --validate`로 입력값을 확인합니다.

**실제 경로에서는 영상 자동 재생이 기본입니다.** --no-video 또는 video.enabled=false일 때만 기존 수동 재생 방식을 사용합니다.
현재 버전은 중간 일시정지·탐색을 지원하지 않습니다. 영상이 멈추거나 시간을 이동하면 시행을 중단하고 처음부터 다시 시작하세요.
video_cue_marker는 시간표상 단서 시각이며 실제 화면 표시를 측정한 값이 아닙니다.

## 로그

기본 터미널 출력은 **한국어 실험 로그**입니다. 경과시간, 좌우, 안내 지점과 함께
사전 안내, 접촉·해제, 수동 점등·소등, 자동 점등·취소, 지점 통과, 오류를 표시합니다.
무시된 접촉도 사유를 표시하며, 천을 떼는 동작은 상태를 바꾸지 않는 입력으로 기록합니다.
반복되는 통신 확인, 명령 응답, 패킷 번호와 같은 내부 처리 기록은 기본 화면에서 숨깁니다.

Proposed에서 취소한 예시(설명용 시각):
```text
[   5.010초] [안내] [demo_straight] 오른쪽 사전 안내 시작 · 자동 점등 취소 가능
[   5.400초] [입력] [demo_straight] 오른쪽 전극 접촉 → 자동 점등 취소
[   5.600초] [입력] [demo_straight] 오른쪽 전극 떼기 → 기록 · 상태 유지
[   7.000초] [취소] [demo_straight] 오른쪽 취소 유지 → 자동 점등하지 않음
```

`status`도 상태를 한국어로 출력합니다. 통신 문제를 살펴볼 때는 실행 명령 끝에 `--verbose`를 붙이면
숨긴 상세 이벤트도 터미널에 추가로 표시합니다. 실험 동작과 저장되는 원본 데이터는 같으며,
펌웨어를 다시 업로드할 필요가 없습니다.

`logs/UTC시각_참가자_시행_조건/`마다 다음을 저장합니다.
- experiment.log: 기본 화면과 같은 읽기 쉬운 한국어 실험 이벤트 기록(UTF-8, 즉시 저장)
- events.csv: 상세 이벤트를 포함한 전체 원본 로그(UTF-8 BOM, 즉시 저장)
- session.json: 해당 시행의 실험 정보, 설정값, 경로 시간표 사본
- mpv_navigation.log / mpv_driving.log: 영상 자동 재생 시 플레이어별 상세 진단 기록

CSV의 열과 기존 이벤트 이름은 유지합니다. CSV에는 UTC 기록 시각, 영상 기준 경과시간,
Pi 단조 시각, 참가자 코드, 시행·조건·경로·지점, 손, 접촉/해제, 처리 결과와 무시 사유,
상태 전후, ESP 기동 후 시간, 패킷 순번, 명령 번호가 들어갑니다.
연결 준비 중, 반대 손, 사전 안내 전, 취소 후, 자동 점등 후의 입력도 기록합니다.
패킷 송수신, 장갑에서 적용된 진동 모드, LED 드라이버 명령, 시간표 지연,
실험자 입력/메모, 통신 오류도 CSV에 그대로 기록합니다.

- input: 안정화된 접촉·해제와 처리 결과
- contact_snapshot: 연결 준비 상태 확인. 새 접촉으로 계산하지 않습니다.
- haptic_applied: 장갑이 GPIO 제어를 적용했다고 보낸 보고. 물리 진동 센서로 측정한 시각은 아닙니다.
- led_driver_on/off: LED 드라이버 호출 결과. 실제 발광 센서 측정값은 아닙니다.
- point_pass: 두 조건 모두 시간표의 pass_s에 자동 소등하고 반복 진동을 정지합니다. Baseline에서 켜둔 채 통과하는 것은 정상 동작이며 manual_off_missed를 생성하지 않습니다. 과거 로그에 남아 있는 해당 이벤트는 당시 규칙의 기록입니다.
- result=ignored는 정답/오답 판정과 다릅니다. 전체 연구 지표 계산은 확정된 분석 기준으로 별도 수행하세요.
- 기본 화면의 점등·소등 문구는 제어 판단을 표시합니다. 실제 발광 여부는 장치에서 확인하세요.
- 화면과 experiment.log는 경과시간을 소수 셋째 자리까지 표시하며, CSV에는 기존 정밀도를 유지합니다.
- ESP device_ms와 Pi 시각은 서로 다른 시계입니다. 두 값을 직접 빼서 무선 지연으로 해석하지 마세요.

## 오류 및 경계 처리

- 두 장갑 연결과 알림 구독, 초기 상태 조회 후 시작합니다.
- 입력 수용 시작은 첫 진동 시작 보고 수신 시점입니다. 무선 전달 시간만큼 실제 모터 시작과 차이가 날 수 있으며 두 시각을 모두 기록합니다.
- 같은 Pi 수신 시각에 입력과 자동 점등/통과 기한이 겹치면 시간표 이벤트를 먼저 처리합니다.
- 연결 해제, 패킷 순번 누락, 잘못된 좌우 펌웨어, 명령 적용 응답 누락, LED 오류는 해당 시행을 무효로 중단합니다.
- 중단 후 LED와 양쪽 진동을 정지합니다. ESP 자체도 연결 해제 또는 4초 동안 명령이 없으면 진동을 멈춥니다.
- 누락된 무선 입력을 복원할 수 있다고 가정하지 않습니다. 자동으로 재접속해 같은 시행을 계속하지 않고, 연결을 복구한 뒤 새 시행으로 시작합니다.

## 연구 운영

각 참가자는 두 경로를 서로 다른 조건으로 1회씩 수행합니다.
참가자 간 조건 순서뿐 아니라 경로-조건 배정도 교차하세요. 이 프로그램은 배정표를 자동 생성하지 않으며 실행 인자로 지정한 값을 기록합니다.
참가자 코드에는 이름 대신 P01 같은 연구용 식별자를 사용합니다.
